# 学割ナビ 要件定義書

> 本書は開発依頼時に提示された要件をもとに整理した要件定義書である。
> （依頼文に「添付の requirements.md」とあったが、実際のファイル添付が確認できなかったため、
> 依頼文の内容をそのまま要件として再構成した。元のファイルが届き次第、差分を確認すること。）

## 1. サービス概要

- サービス名：学割ナビ
- 目的：高校生が利用できる学割のある飲食店、カラオケ、映画館、娯楽施設などの情報を投稿・共有できるWebサービス
- キャッチコピー：「放課後を、もっとおトクに。」
- 想定ユーザー：高校生（スマートフォン利用が中心）

## 2. 課題の評価項目（全7項目の達成を目指す）

1. requirements.md による要件定義（本書）
2. 静的サイトを Azure App Service で公開
3. Azure Blob Storage から画像を表示
4. GitHub への push による App Service への自動デプロイ
5. Flask による掲示板の実装
6. Azure Table Storage への投稿データ保存
7. Azure Blob Storage への画像投稿

進め方：まず必須項目を満たす静的版を完成させ、その後 Flask + Azure Storage の動的版へ発展させる。
静的版も成果物として保持する。Azure Static Web Apps ではなく Azure App Service を使用する。

## 3. 技術スタック

- HTML5 / CSS / JavaScript
- Python / Flask / Jinja2
- Tailwind CSS / daisyUI（可能な限りビルド済みCSSを使用）
- Lucide Icons
- Azure App Service / Azure Blob Storage / Azure Table Storage
- GitHub Actions
- フロントエンドのためだけに React や Next.js は導入しない

## 4. デザイン要件

- メインカラー：エメラルドグリーン、アクセント：ライムグリーン、背景：白または薄いグレー
- フォント：日本語 Noto Sans JP、英数字 Inter
- 写真を活用したカード型UI、十分な余白、統一された角丸、控えめなホバーアニメーション
- Lucide Icons でアイコンを統一
- レスポンシブデザイン、スマートフォンでは下部ナビゲーション
- 過度なグラデーション、ネオンカラー、不必要なアニメーション、絵文字の多用は避ける
- 参考：Airbnb、Instagram、現代的なクーポンアプリ（模倣ではなく独自デザイン）

## 5. ページ構成

### 5.1 トップページ
- サービスロゴ、キャッチコピー
- 店舗名・駅名による検索欄
- ジャンル別・エリア別の絞り込み
- 新着学割情報、人気の学割情報、学割情報のカード一覧
- 新規投稿ボタン

### 5.2 学割詳細ページ
- 店舗名、店舗画像、学割内容、通常価格と学割価格、最寄り駅
- 利用条件、対象学年、有効期限、情報確認日、公式サイトへのリンク
- コメント一覧、コメント投稿機能

### 5.3 新規投稿ページ
- 店舗名、ジャンル、エリア、最寄り駅、学割内容、通常価格、学割価格
- 利用条件、有効期限、公式サイトURL、画像アップロード（プレビュー付き）、投稿ボタン

## 6. 独自機能

- 通常価格と学割価格から割引率を自動計算
- 割引率順、新着順、価格順での並び替え
- 情報確認日の表示
- 有効期限が過ぎた学割の終了表示
- コメントによる学割情報の更新・訂正
- お気に入り機能（LocalStorage）

## 7. Azure連携

- 投稿データとコメントは Azure Table Storage に保存
- 画像は Azure Blob Storage に保存し、Webサイトから閲覧可能にする
- 画像コンテナーは原則非公開とし、Flask経由で画像を配信するなど安全な方法を採用
- 可能であればマネージドIDを利用。権限不足の場合は App Service の環境変数（接続文字列）方式も用意
- Azure未設定でもローカルで開発・動作確認できること（ローカル保存とAzure保存を明確に区別）

## 8. セキュリティ要件

- GitHubリポジトリは Public
- 秘密情報（SASトークン、発行プロファイル、接続文字列、アクセスキー、APIキー、.env）を絶対にコミットしない
- .gitignore と .env.example を作成
- XSS対策、CSRF対策、入力値検証、画像ファイルの形式・サイズ制限
- 投稿の連投制限、不適切な投稿への対応手段（通報機能）
- 本名・学校名・学生証などの個人情報を投稿しないよう注意事項を表示

## 9. サンプルデータ

- 初期状態で完成したサービスに見えるよう12件程度のサンプルデータを用意
- 飲食店、カラオケ、映画館、娯楽施設など複数ジャンルを含める
- 架空の店舗・割引情報はデモデータであることを明記し、実在店舗の未確認の学割情報は掲載しない
- 画像は自作または利用許諾の確認できる素材を使用

## 10. 開発後の確認

- PC表示、スマートフォン表示、検索と絞り込み、新規投稿、コメント投稿、画像アップロード、画像表示
- データの永続化、エラー時の表示、秘密情報の混入、Azureへのデプロイ設定
- スクリーンショットを撮影し、デザインに問題があれば改善する
- 動作しないダミー機能を可能な限り残さない

## 11. 納品物

- Webサイトの全ソースコード、requirements.md、requirements.txt、README.md
- .gitignore、.env.example、GitHub Actions設定ファイル
- Azureの設定・デプロイ手順書、静的サイト版
- PC・スマートフォンのスクリーンショット
- 実装済み機能と未実装機能の一覧、ソースコード一式のZIPファイル

## 12. 制約

- 有料リソースの作成、課金、外部公開はユーザーの承認なしで実行しない
- 未実施のテストやデプロイを成功したと報告しない
- Azure / GitHub の認証が必要な操作は、ユーザーが行う操作だけをまとめて報告する
